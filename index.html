GNOME Wayland
computer use.

Cua owns control. This project makes Cua feel native on Ubuntu GNOME Wayland: the right host foundation, Cua's own Mutter helper, deterministic agent routing, and a fast independent whole-screen observer.

Ubuntu 26.04GNOME 50WaylandCua DriverScreenCast + PipeWire

Architecture

CUA DRIVER → controlSemantics, target pixels, WinRects geometry, exact activation, portal/libei input, cursor state, verification, and structured refusals.
GWCU → observationLazy XDG ScreenCast + PipeWire whole-screen evidence for explicit screen requests and discovery.
THE AGENT → intentChooses what should happen. It does not reconstruct toolkit mechanics, focus policy, or raw-input fallbacks.

Install

curl -fsSL https://ryanraposo.github.io/gnome-wayland-computer-use/install.sh | bash

One installer. It repairs missing Ubuntu foundation, installs current Cua through the official installer, provisions Cua's packaged WinRects helper, installs the skill, enables the private observer, and verifies the finished state.

No project uinput stack. No ydotool daemon. No custom Cua daemon. No parallel WinRects client.

Normal task

known target
  → one Cua target state
  → AX when grounded / PX from the same state
  → consume Cua effect + verification
  → exact foreground only when Cua requires it
  → respect refusal

Whole screen

~/.agents/skills/gnome-wayland-computer-use/scripts/observe.sh --media --screen

The observer is socket-activated and keeps a portal-scoped PipeWire stream warm only during a task burst. Login itself never opens capture consent.

Ready means ready

The installer finishes with READY, or tells you the one honest remaining platform transition: a GNOME sign-out/in to load a new Cua WinRects helper. Machine diagnostics use the same rule: top-level ok means the current session is actually ready.

The agent decides intent. Cua decides mechanics.
