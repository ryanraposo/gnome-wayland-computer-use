A shell subprocess is cheap. A model/tool boundary is expensive. GWCU lets scripts compose scripts locally so the agent receives one structured route or recovery verdict instead of paying for probe → interpret → probe → interpret.

One clean ownership model

CUA DRIVER → CONTROL

Semantic + pixel actions, target state, GNOME geometry, exact activation, portal input, cursor, effects, verification, escalation, refusals.

GWCU → SYSTEM

Ubuntu qualification, dependency repair, cached routing context, deterministic recovery, and a private warm ScreenCast/PipeWire observer.

AGENT → INTENT

Chooses the outcome. Known targets go directly to Cua; uncertainty is collapsed by local programs instead of model deliberation.

The hot path

known target → one Cua target/window state → AX when grounded / PX from that same state → useful action span → verify only when the next decision depends on it

Zero task-time update checks. Zero broad diagnostics. Zero known-target enumeration. Zero whole-screen prelude when target evidence is enough. Zero blind replay of the same failed delivery shape.

Scripts compose scripts

uncertain target → profile.sh route "NAME" → cached session context → deterministic launcher/PWA identity → one gwcu.route.v1 answer host contradiction → profile.sh recover → cached profile read → refresh only if stale/missing → diagnose.sh → Cua health + GNOME observation facts → one gwcu.route.v1 answer

Routing never wakes diagnostics merely because launcher identity is uncertain. Recovery is deliberately the expensive path, but its internal fan-out still costs the agent one call.

Native Ubuntu substrate

Use the pieces Ubuntu already has. Qualify them once.

The installer repairs the explicit portal/PipeWire/AT-SPI foundation, pins Cua 0.19.3, installs Cua's packaged GNOME helper, starts the private observer socket, and treats cua-driver doctor --json as a hard readiness gate. It does not install a parallel raw-input stack.

Portal consent

01
Remote Desktop / control

The first Cua foreground input may ask for GNOME remote-control consent. Approval creates the portal-issued EIS/libei input session. No X11 session is required.

02
ScreenCast / observation

The first explicit whole-screen observation may separately ask which screen to share. GWCU keeps the portal-scoped PipeWire stream warm only while useful.
