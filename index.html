One clean ownership model

CUA DRIVER → CONTROL

Semantic + pixel actions, target state, GNOME geometry, exact activation, portal input, cursor, effects, verification, escalation, refusals.

GWCU → INTEGRATION + OBSERVATION

The hot path

known target → one Cua target/window state → AX when grounded / PX from that same state → consume effect + verification + escalation → exact foreground only when Cua requires it → respect structured refusal

No task-time update checks. No broad diagnostics. No whole-screen prelude when target evidence is enough. No blind replay of the same failed delivery shape.

Portal consent, honestly

01
Remote Desktop / control

The first Cua foreground input may ask for GNOME remote-control consent. Approve it and Cua uses the portal-issued EIS/libei route. No X11 session required.

02
ScreenCast / observation

The first explicit whole-screen observation may separately ask which screen to share. GWCU keeps that portal-scoped PipeWire stream warm only while useful.

Installer

Distro-aware. Elevated when necessary. Pinned upstream. Doctor-gated before success.

The installer reads /etc/os-release, repairs the explicit Ubuntu 26 portal/PipeWire/AT-SPI stack, verifies PipeWire ≥ 0.3.40 and GNOME's RemoteDesktop/ScreenCast/Screenshot interfaces, installs Cua 0.19.3 through Cua's official installer, installs Cua's own WinRects helper, enables the private observer socket, and fails loudly on a non-zero cua-driver doctor.

No custom udev rule is required. A video group change is considered only when Cua doctor actually reports a DRM/render-node permission problem.

Uninstall

curl -fsSL https://ryanraposo.github.io/gnome-wayland-computer-use/uninstall.sh | bashreversible ownership

Removes project skills, observer units, managed PATH edits, routing, accessibility changes, and any GWCU-added video membership. Cua is removed only if GWCU provisioned it; a pre-existing Cua install is preserved. Ubuntu desktop packages stay host-owned.
