Native capture. GNOME-aware control.

Screen observation uses XDG ScreenCast + PipeWire and remains independent of Shell helpers. The project-owned desktop-capture extension is retired. For the full Hermes/Cua profile, Cua's bundled winrects@cua adapter supplies authoritative Mutter geometry and verified activation through Cua itself.

capture.sh never calls WinRects and this project never vendors its protocol.

Ubuntu already has the foundation.

Ubuntu 26.04 GNOME normally ships PipeWire and WirePlumber. The installer verifies that native foundation first, then repairs missing official portal/PipeWire/GStreamer packages only when a host is incomplete.

Fast capture after one real permission.

The hot path is ScreenCast + PipeWire. Persistent restore tokens turn the monitor chooser into a first-use/revocation boundary. Screenshot portal and Shift+Print are recovery, not steady-state architecture.

CAPTURE="$HOME/.agents/skills/gnome-wayland-computer-use/scripts/capture.sh"
"$CAPTURE" --timing --screen /tmp/screen.png

Preserve foreground. Escalate truthfully.

Semantic background comes first. Then target-addressed semantic/pixel delivery. If a task genuinely requires focus-bound input, Cua activates and verifies the intended GNOME target before delivery. Unsafe occluded delivery refuses instead of guessing.

Pixel-only means pixel-only.

A Vulkan or GLFW window can be visibly real while exposing no useful AT-SPI tree. Pixels establish visual existence; Cua WinRects may still make that window precisely addressable. No repeated AX séance required.

Installed web apps stay apps.

Standalone browser-backed apps keep their own identity through live window data, desktop IDs, StartupWMClass, --app-id=, and --app=.

Route once → cheapest truthful evidence.

AX for semantics. ScreenCast for pixels. Cua/Mutter precision where GNOME knowledge adds real capability. Fresh evidence at actual decision boundaries.
